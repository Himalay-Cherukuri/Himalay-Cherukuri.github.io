## 1. Purpose
This is a calm, readable study and reference site for *Kautilya's Arthashastra* (tr. R. Shamasastry). The content is organised in four levels:
**Book (15) > Chapter (150) > Topic (228) > Paragraph (3,351)**, and 1,848 tagged terms are linked to the paragraphs they appear in.
Readers must be able to browse the hierarchy, cite any paragraph by its ID, jump to topics, and look up terms.

Claude's job is to design **one template** plus its CSS and JS. A local Python script will fill the template once for each page, using `map.json` and `tags.json`.

## 2. Data model (real field names)

### map.json
```
{ meta:{title, page_count, id_scheme, counts:{books,chapters,topics,paragraphs,tag_terms,tag_links}},
  front_matter:{...}, duplicates:[...],      // ignore for design
  books:[ Book ] }
Book      { id:"B01", num:1, roman:"I", title:"Concerning Discipline", slug:"discipline",
            page_start, page_end, heading_raw, path, chapters:[Chapter] }
Chapter   { id:"B01.C02", book_num:1, num:2, roman:"II", global_seq:2,
            title:"The End of Sciences", slug:"end-sciences", page_start, page_end,
            end_marker:{raw, ...}, path, topics:[Topic] }
Topic     { id:"B01.C02.T1", num:1, title, slug, source, page_start, page_end, path,
            paragraphs:[Paragraph] }
Paragraph { id:"B01.C02.T1.P001", num:1,
            type: "paragraph" | "verse" | "list_item" | "citation" | "end_marker",
            text, words, page_start, page_end,
            tags:{ office:[...], sanskrit:[...], number:[...], amount:[...], unit:[...], penalty:[...] } }
```
ID scheme: `B##` > `B##.C##` > `B##.C##.T#` > `B##.C##.T#.P###`. IDs contain dots, so CSS selectors must escape them, or JS should use `getElementById`.

### tags.json
```
{ "<category>": { "<term>": { count: 59, paragraphs: ["B02.C07.T1.P027", ...] } } }
```
Categories: `office` (king, priest...), `sanskrit` (accented terms), `number`, `amount` (e.g. "12 panas"), `unit` (angulas...), `penalty` (fine...).

### search_index.json (generated by the script, consumed by app.js)
```
[ { "id":"B01.C02.T1.P001", "t":"<paragraph text, may be truncated>",
    "b":"Book I", "c":"The End of Sciences", "u":"/B01_discipline/C02_end-sciences.html#B01.C02.T1.P001" },
  { "id":"tag:office:king", "t":"king", "k":"tag", "u":"/tags/office/king.html" } ]
```

## 3. Site map and URL scheme
Folder names are `B{nn}_{book.slug}`. Chapter files are `C{nn}_{chapter.slug}.html`. The numbers are zero-padded to 2 digits.
```
/index.html                                  Home
/B01_discipline/index.html                   Book page
/B01_discipline/C02_end-sciences.html        Chapter page (topics + paragraphs inline)
   #B01.C02.T1                               topic anchor
   #B01.C02.T1.P001                          paragraph anchor
/tags/index.html                             All terms grouped by category
/tags/{category}/{term-slug}.html            Term page
/search.html                                 Search page
/assets/styles.css  /assets/app.js  /assets/search_index.json
```
All links that the script injects are root-relative (`/assets/...`). The template should use `{{root}}` as the prefix, so the site also works when opened from `file://` (see placeholders).

## 4. Page types and layout
Every page type uses the same 3-column shell:

```
+------------------------------------------------------------------+
| header: site title · search box · theme toggle · menu btn(mobile)|
+-----------+------------------------------------+-----------------+
| sidebar   | breadcrumbs                        | On this page    |
| 15 books, | h1 page title + meta line          | (topic list,    |
| collaps-  | content                            |  scroll-spy)    |
| ible      | tag chips                          |                 |
| chapters  | prev / next                        |                 |
+-----------+------------------------------------+-----------------+
| footer                                                           |
+------------------------------------------------------------------+
```

- **Home**: a title, a short intro, the counts from `meta.counts`, and a grid of 15 book cards (roman, title, chapter count, page range). There is no right TOC.
- **Book**: `Book {roman}: {title}`, page range, and an ordered chapter list (roman, title, topic count). The right TOC lists the chapters.
- **Chapter**: `Chapter {roman}: {title}`, with a meta line showing `{id} · Book {roman}: {book title} · p. {page_start}-{page_end}`. Each topic gets a `<section id="{topic.id}">` with an h2. Each paragraph renders as below. The `end_marker` paragraph is shown as a muted colophon. The right TOC lists the topics. Prev/next go to the neighbouring chapters by `global_seq`, crossing book boundaries.
- **Term**: the term, its category, a count, and a list of paragraph references (ID, chapter title, and a text snippet), each linking to its anchor.
- **Search**: one input and a results list, filtered client-side from `search_index.json`.

### Paragraph markup (the script emits this inside `{{content}}`; please style it)
```html
<p class="para para--{type}" id="{id}" data-page="{page_start}">
  <a class="para-id" href="#{id}" title="Copy link">{id short e.g. P001}</a>
  {text}
  <span class="para-page">p.{page_start}</span>
  <span class="para-tags"><a class="chip chip--office" href="...">king</a>...</span>
</p>
```
Type styles:
- `verse`: indented, italic, with a left rule. The real data uses `<p class="para para--verse">`.
- `list_item`: a hanging indent.
- `citation`: smaller, muted.
- `end_marker`: centred, small caps, muted.

Paragraph tag chips stay hidden until the paragraph is hovered or focused, or until "Show tags" is turned on.

### Sidebar
`{{sidebar}}` is a nested list in this form: `<nav><ul class="tree"><li class="book [is-open]"><button aria-expanded>I · Concerning Discipline</button><ul><li class="chapter [is-current]"><a href>II · The End of Sciences</a></li>...`. app.js handles the collapse and expand, and remembers the open books in localStorage. The current book starts open, and the current chapter is highlighted and scrolled into view.

## 6. Visual direction
- **Typography**: a serif body (system stack: `Iowan Old Style, Charter, Georgia, serif`), about 18–19px, line-height 1.65, a measure of about 70ch. Headings and UI use a sans system stack. Diacritics (á, é, ó) must render well. No web-font downloads.
- **Palette**: calm and parchment-like. Light mode uses a warm off-white background, deep ink text, and a muted terracotta or saffron accent. Dark mode uses a deep slate background, soft ivory text, and the same accent desaturated. Define everything as CSS custom properties. Follow `prefers-color-scheme`, add a toggle that persists in localStorage, and give each tag category a subtle colour.
- **Responsive**: 3 columns at ≥1200px; at ≥800px the right TOC is hidden or folds under the h1; below 800px the sidebar becomes an off-canvas drawer opened by the menu button.
- **Accessible**: semantic landmarks (`header`, `nav`, `main`, `aside`, `footer`), a skip-to-content link, visible focus rings, WCAG AA contrast in both themes, `aria-expanded` on toggles, full keyboard support, and `prefers-reduced-motion` respected.
- **Print**: hide the chrome and print the reading pane only, with paragraph IDs visible.

## 7. app.js responsibilities (vanilla, about 200 lines or less)
1. Theme toggle and persistence.
2. Sidebar collapse, persistence, and the mobile drawer.
3. Scroll-spy that highlights the current topic in `{{toc}}`.
4. Clicking a `.para-id` copies the deep link to the clipboard and shows a small toast.
5. Search: lazy-fetch `{{root}}assets/search_index.json` on first focus or on the search page, do a case- and diacritic-insensitive substring match (`normalize('NFD')`), show the top 50 results with the match highlighted, and support `?q=` on search.html. The header search box submits to search.html.
6. Keyboard shortcuts: `/` focuses search, `[` and `]` go to the previous and next chapter.
7. A "Show tags" toggle for the paragraph chips.
8. Highlight the `:target` paragraph when the page loads.
